# 設計書：対応関係マッチング問題（type: "matching"）

## 1. 概要

左列・右列の項目を順番に選んでペアを作り、対応関係の正誤を確認する問題形式。  
既存の `"single"` / `"multiple"` に加えて `"matching"` を新しい問題タイプとして追加する。

---

## 2. JSON スキーマ変更

### 2-1. `quiz.schema.json` の変更方針

既存の `questions` 配列の `items` に `oneOf` を導入し、問題タイプで分岐させる。

```
questions.items
  ├── oneOf[0]: type = "single" または "multiple"（既存）
  └── oneOf[1]: type = "matching"（新規）
```

### 2-2. `matching` タイプのフィールド定義

| フィールド | 型 | 必須 | 説明 |
|---|---|:---:|---|
| `id` | integer | ✓ | 問題番号（問題集内でユニーク） |
| `type` | `"matching"` | ✓ | 問題タイプ識別子 |
| `question` | string | ✓ | 問題文（Markdown可） |
| `left` | array of string | ✓ | 左列の項目リスト（2〜8個） |
| `right` | array of string | ✓ | 右列の項目リスト（左と同数） |
| `pairs` | array of `[number, number]` | ✓ | 正解の対応関係。各要素は `[左インデックス, 右インデックス]` |
| `explanation` | string | ✓ | 解説テキスト（Markdown可） |
| `deprecated` | boolean | — | 廃止・出題注意フラグ（省略時 false） |
| `deprecation_note` | string | — | 廃止理由 |
| `skip` | boolean | — | 出題除外フラグ（省略時 false） |
| `skip_note` | string | — | スキップ理由 |
| `note` | string | — | 補足・注意事項 |

> `choices` / `answer` / `answer_count` / `explanation_table` は `matching` タイプでは**使用しない**。

### 2-3. JSON サンプル

```json
{
  "id": 101,
  "type": "matching",
  "question": "拡張イベントの各ターゲットと、その説明を正しく組み合わせてください。",
  "left": [
    "event_file",
    "ring_buffer",
    "event_counter",
    "pair_matching"
  ],
  "right": [
    "メモリに一時保存（上書き循環、セッション終了で消える）",
    "回数を数えるだけ",
    "対になるイベントの片方だけを検出",
    "ファイルに永続保存"
  ],
  "pairs": [
    [0, 3],
    [1, 0],
    [2, 1],
    [3, 2]
  ],
  "explanation": "event_file はファイルへの永続保存、ring_buffer はメモリへの一時保存（循環上書き）、event_counter はイベントの発生回数を集計するだけ、pair_matching は対になるイベントの片方を検出するターゲットです。"
}
```

> `pairs` は `right` の**元インデックス**で定義する。出題時に `right` をシャッフルしても正解判定は正しく行われる。

## 4. UI コンポーネント仕様

### 4-1. 選択形式バッジ

| 問題タイプ | バッジ表示 |
|---|---|
| `single` | `一つ選択` |
| `multiple` | `2つ選択`（answer_count に依存） |
| `matching` | `マッチング` |

### 4-2. 左列ボタンの状態

| 状態 | スタイル | クリック |
|---|---|---|
| 未選択・未確定 | `btn-outline-secondary` | 選択開始（ハイライト） |
| 選択中（右列待ち） | `btn-primary`（青） | 再クリックで選択解除 |
| ペア確定済み | `btn-outline-secondary disabled` | 無効 |
| 採点後 | 変更なし（バッジ色で表現） | 無効 |

### 4-3. 右列ボタンの状態

| 状態 | スタイル | クリック |
|---|---|---|
| 左列未選択時 | `btn-outline-secondary disabled` | 無効 |
| 左列選択中・選択可 | `btn-outline-secondary` | ペア確定 |
| ペア確定済み | `btn-outline-secondary disabled` | 無効 |
| 採点後 | `btn-outline-secondary disabled` | 無効 |

### 4-4. バッジ（確定ペアの表示）

左列ボタンの右隣にインライン表示。

| 採点前 | `badge bg-secondary` + 右列項目テキスト |
|---|---|
| 採点後・正解 | `badge bg-success` + テキスト + ` ✓` |
| 採点後・不正解 | `badge bg-danger` + テキスト + ` ✗` + 正解テキストを行下に補足 |

### 4-5. ボタン

| ボタン | 初期状態 | 有効化条件 | 動作 |
|---|---|---|---|
| やり直し | 常に有効 | — | 全ペアをクリア、選択状態をリセット |
| 答え合わせ | `disabled` | 全ペア確定時 | 採点・解説表示、次の問題を有効化 |
| 次の問題 | `disabled` | 採点後 | 次問へ遷移（最終問題は「結果を見る」） |

## 5. JavaScript 設計

### 5-1. 状態管理変数

```js
// matching 問題専用の状態
let matchingState = {
  shuffledRight: [],      // シャッフル後の right 配列（表示順）
  shuffleMap: [],         // shuffledRight[i] = 元インデックス の対応
  selectedLeft: null,     // 現在選択中の左インデックス（null = 未選択）
  confirmedPairs: {},     // { 左インデックス: シャッフル後右インデックス }
  answered: false
};
```

### 5-2. 初期化処理（問題表示時）

```
1. matchingState を初期化
2. right 配列をシャッフルして shuffledRight・shuffleMap を生成
3. 左列ボタンを描画（left 配列の順で固定）
4. 右列ボタンを描画（shuffledRight の順）
5. localStorage に解答済みデータがあれば復元して採点後表示
```

### 5-3. シャッフルロジック

```js
// Fisher-Yates シャッフル
function shuffleRight(right) {
  const indices = right.map((_, i) => i);
  for (let i = indices.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [indices[i], indices[j]] = [indices[j], indices[i]];
  }
  return {
    shuffledRight: indices.map(i => right[i]),  // 表示テキスト
    shuffleMap: indices                          // shuffledRight[i] の元インデックス
  };
}
```

### 5-4. クリックイベント処理

```
【左列クリック】
- 確定済みの行 → 無視
- 未選択状態 → selectedLeft に設定、青ハイライト、右列を有効化
- 再クリック（同じ左）→ 選択解除、右列を無効化

【右列クリック】
- selectedLeft が null → 無視（ボタンは disabled なので通常到達しない）
- ペア確定: confirmedPairs[selectedLeft] = クリックした右インデックス
- 左列ボタンにバッジを表示、左右ともに該当ボタンを disabled 化
- selectedLeft = null にリセット
- 全ペア確定なら「答え合わせ」ボタンを有効化
```

### 5-5. 採点処理

```js
function gradeMatching(q, confirmedPairs, shuffleMap) {
  let correct = 0;
  const results = {};  // { 左インデックス: boolean }

  q.pairs.forEach(([leftIdx, rightOrigIdx]) => {
    const userShuffledIdx = confirmedPairs[leftIdx];
    const userOrigIdx = shuffleMap[userShuffledIdx];
    const isCorrect = userOrigIdx === rightOrigIdx;
    results[leftIdx] = { correct: isCorrect, correctOrigIdx: rightOrigIdx };
    if (isCorrect) correct++;
  });

  return { correct, total: q.pairs.length, results };
}
```

### 5-6. localStorage への保存形式

既存の問題と同じキー（`quiz_progress_{問題集ID}`）に以下を追記する。

```json
{
  "101": {
    "answered": true,
    "correct": false,
    "selected": {
      "pairs": [[0, 3], [1, 0], [2, 2], [3, 1]],
      "shuffleMap": [3, 0, 2, 1]
    }
  }
}
```

| フィールド | 説明 |
|---|---|
| `answered` | 採点済みかどうか |
| `correct` | 全ペア正解なら `true`（部分正解は `false`） |
| `selected.pairs` | ユーザーが確定したペア `[左インデックス, シャッフル後右インデックス]` の配列 |
| `selected.shuffleMap` | 出題時のシャッフル順。復元時に正解判定に使用 |

### 5-7. 解答済み問題への再訪（復元処理）

1. localStorage から `selected.pairs` と `selected.shuffleMap` を取得
2. `shuffleMap` を使って右列を同じ順序で復元
3. `pairs` を `confirmedPairs` に復元
4. 採点後の表示状態（バッジ色・解説表示）を再描画
5. 全ボタンを `disabled` にする

## 6. 既存コードへの影響範囲

| 対象ファイル | 変更内容 |
|---|---|
| `quiz.html` | マッチング問題用のHTML構造を追加（左列・右列・バッジ領域） |
| `app.js` | 問題タイプ判定に `"matching"` を追加。描画・採点・localStorage処理を追加 |
| `schema/quiz.schema.json` | `questions.items` を `oneOf` 構造に変更し、`matching` タイプ定義を追加 |
| `style.css` | マッチング問題専用のレイアウト（左右列の横並び・スマホ縦積み）を追加 |

### 既存問題タイプへの影響

- `"single"` / `"multiple"` の処理は変更しない
- 問題タイプの分岐は `if (q.type === 'matching')` で独立させ、既存処理に手を入れない

## 7. レスポンシブ対応

| 画面幅 | 左列・右列の配置 |
|---|---|
| 768px 以上（デスクトップ） | 横並び（`display: flex; gap`） |
| 768px 未満（スマホ） | 縦積み（左列→右列の順） |

スマホでは右列は左列の下に表示し、「左を選ぶ → 下にスクロールして右を選ぶ」という自然な操作フローになる。

## 8. アクセシビリティ対応

| 要素 | 対応 |
|---|---|
| 左列ボタン（選択中） | `aria-pressed="true"` |
| 右列ボタン（無効時） | `disabled` 属性で読み上げから除外 |
| バッジ | `aria-label` で「ペア: event_file → ファイルに永続保存、正解」などを付与 |
| 採点結果行（「2 / 4 ペア正解」） | `aria-live="assertive"` |
| 解説エリア | 既存の `aria-live="polite"` を流用 |
