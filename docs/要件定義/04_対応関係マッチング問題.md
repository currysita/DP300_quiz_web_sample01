# 要件定義書：対応関係マッチング問題（バッジ形式）

## 1. 概要

### 目的

左列の項目と右列の項目を順番に選んでペアを作り、対応関係の正誤を確認する問題形式を追加する。

テーブル構造の暗記（例：拡張イベントのターゲットとその説明、プラットフォーム対応の有無）に適した出題形式。

### 位置付け

既存の「単一選択問題（`single`）」に加える新しい問題タイプ（`matching`）として追加する。

---

## 2. 問題タイプの定義

JSON スキーマに新しい `type` 値として `"matching"` を追加する。

---

## 3. 操作フロー

```
① 左列の項目を1つタップ／クリック → ハイライト表示
② 右列の項目を1つタップ／クリック → ペア確定
   → 左項目の右隣にバッジとして表示（例: [ファイルに永続保存 ×]）
③ ①②を繰り返して全ペアを作成
④ 「答え合わせ」ボタンを押す → 採点・解説表示
⑤ 「やり直し」ボタンで全ペアをリセット → ①に戻る
```

---

## 4. UI 仕様

### 4-1. 問題表示エリア

- 問題文を表示する（既存と同じ）
- 左列・右列をそれぞれ縦に並べて表示する
- 左列・右列は画面幅に応じて横並び（デスクトップ）または縦並び（スマホ）にする

### 4-2. 左列

- 選択肢（左側の項目）をボタン形式で縦に並べる
- 未選択：通常スタイル
- 選択中（右列待ち）：ハイライト（青系）
- ペア確定済み：ボタンを非活性化または選択不可にする

### 4-3. 右列

- 選択肢（右側の項目）をボタン形式で縦に並べる
- 左列で何かを選択した状態のみ選択可能にする（左列未選択時は右列を無効化）
- 選択済み（いずれかの左項目とペアになった）項目は非活性化する

### 4-4. バッジ表示

- 左列の各ボタンの右隣に、対応付けた右列の項目名をバッジとして表示する
- バッジには「×」ボタンは付けない（取り消しは全リセットのみ）
- 採点前：グレー系のバッジ
- 採点後 正解：緑系のバッジ
- 採点後 不正解：赤系のバッジ（正解の右列項目名も表示する）

### 4-5. ボタン

| ボタン | 表示条件 | 動作 |
|---|---|---|
| 答え合わせ | 全ペアが揃った時点で有効化 | 採点・解説を表示 |
| やり直し | 常に表示 | 全ペアをリセットして最初から |

### 4-6. 採点・解説表示

- 既存の単一選択問題と同様に、採点後に解説テキストを表示する
- 正解数 / 総ペア数（例：3 / 5 ペア正解）を表示する
- 「次の問題」ボタンは採点後に有効化する（採点前は無効）

---

## 5. JSON データ形式

### 5-1. フィールド定義

| フィールド | 型 | 必須 | 説明 |
|---|---|:---:|---|
| `type` | `"matching"` | ✓ | 問題タイプ |
| `id` | string | ✓ | 問題ID（既存と同じ） |
| `question` | string | ✓ | 問題文 |
| `left` | array of string | ✓ | 左列の項目リスト |
| `right` | array of string | ✓ | 右列の項目リスト（シャッフル対象） |
| `pairs` | array of `[left_index, right_index]` | ✓ | 正解の対応関係（左インデックス→右インデックス） |
| `explanation` | string | ✓ | 解説テキスト |
| `deprecated` | boolean | — | 廃止・出題注意フラグ（既存と同じ） |
| `skip` | boolean | — | 出題除外フラグ（既存と同じ） |

### 5-2. サンプル JSON

```json
{
  "type": "matching",
  "id": "q_ext_event_target_01",
  "question": "拡張イベントの各ターゲットと、その説明を正しく組み合わせてください。",
  "left": [
    "event_file",
    "ring_buffer",
    "event_counter",
    "pair_matching"
  ],
  "right": [
    "メモリに一時保存（上書き循環、セッション終了で消える）",
    "回数を数えるだけ",
    "対になるイベントの片方だけを検出",
    "ファイルに永続保存"
  ],
  "pairs": [
    [0, 3],
    [1, 0],
    [2, 1],
    [3, 2]
  ],
  "explanation": "event_file はファイルへの永続保存、ring_buffer はメモリへの一時保存（循環上書き）、event_counter はイベントの発生回数を集計するだけ、pair_matching は対になるイベントの片方を検出するターゲットです。"
}
```

> **注意**: `right` の並び順は出題時にシャッフルする。`pairs` は元のインデックスで定義するためシャッフル後も正解判定は正しく行われる。

---

## 6. スキーマ変更方針

`schema/quiz.schema.json` に `"matching"` タイプ用の定義を追加する。

既存の `"single"` タイプとは `oneOf` または `if/then` で分岐させ、`matching` タイプにのみ `left` / `right` / `pairs` フィールドを要求する。

---

## 7. 採点ロジック

- ユーザーが作ったペア（`left_index → right_index`）と `pairs` の正解を比較する
- 1ペアでも一致すれば部分点ではなく、全ペア一致のみ「この問題は正解」とする
  - ただし画面上は「3 / 5 ペア正解」のように部分的な結果を表示する
- `localStorage` への保存は既存の `correct / incorrect` 二値で管理する（全一致なら `correct`）

---

## 8. 対象外（今回のスコープに含まない）

- 線でつなぐ形式のドラッグ＆ドロップ
- チェックボックス表形式（プラットフォーム対応表など多対多の対応）
- 個々のペアへの部分点の付与
- ペア単位での取り消し（全リセットのみ対応）
