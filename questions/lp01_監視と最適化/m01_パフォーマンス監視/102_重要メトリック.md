# 監視102 — 重要なパフォーマンスメトリックの説明

> 対応ユニット: [重要なパフォーマンス メトリックの説明](https://learn.microsoft.com/ja-jp/training/modules/describe-performance-monitoring/3-describe-critical-performance-metrics)

---

## 問題 1

Azure Monitor のメトリック アラートについて正しい説明はどれですか？

- A. アラートはサブスクリプション内の単一リソースにのみ設定できる
- B. メトリック データは無期限に保存される
- C. アラートの条件は静的しきい値または動的しきい値で設定できる
- D. アクション グループを設定しないとアラート ルールは作成できない

<details>
<summary>解答・解説</summary>

**解答:** C

Azure Monitor のアラートは静的しきい値（例: CPU が 80% 超）でも、動的しきい値（メトリックの履歴動作を学習して異常を検知）でも設定できます。アクション グループは省略可能で、設定しなくてもアラートは作成・記録されます。メトリックの保存期間は 93 日間です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. 単一リソースのみ | リソース グループ・サブスクリプション単位でも設定可能 | ❌ |
| B. 無期限保存 | Azure Monitor メトリックの保存期間は 93 日間 | ❌ |
| C. 静的・動的しきい値 | 両方サポート | ✅ 正解 |
| D. アクション グループ必須 | 省略可能。未設定でも通知がストレージに記録される | ❌ |

</details>

## 問題 2

Azure Monitor のアラート スコープとして設定できないものはどれですか？

- A. サブスクリプション内の特定リージョンの仮想マシン一覧
- B. サブスクリプション内の特定リソース グループ内の全 VM
- C. サブスクリプション内の全 VM（特定リージョン）
- D. 複数サブスクリプションにまたがる全 VM

<details>
<summary>解答・解説</summary>

**解答:** D

Azure Monitor のアラート スコープは、1 サブスクリプション内で VM 一覧・リソース グループ・サブスクリプション全体の 3 段階で設定できます。複数サブスクリプションをまたぐスコープは単一アラート ルールとしてはサポートされていません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. 特定リージョンの VM 一覧 | スコープとして設定可能 | ❌（設定できる） |
| B. リソース グループ内の全 VM | スコープとして設定可能 | ❌（設定できる） |
| C. サブスクリプション内の全 VM | スコープとして設定可能 | ❌（設定できる） |
| D. 複数サブスクリプションの全 VM | サポートされない | ✅ 正解（設定できない） |

</details>

## 問題 3

Azure Monitor のアクション グループで設定できるアクションに含まれないものはどれですか？

- A. Azure Automation Runbook の実行
- B. Webhook の呼び出し
- C. Azure SQL Database のデータベース バックアップの実行
- D. Azure Logic App のトリガー

<details>
<summary>解答・解説</summary>

**解答:** C

アクション グループで定義できるアクションには、Automation Runbook・Azure Functions・Logic App・Webhook・ITSM・メール/SMS などがあります。データベース バックアップの実行はアクション グループの直接オプションではなく、Runbook 等を介して間接的に実行します。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Automation Runbook | アクション グループのオプションに含まれる | ❌（設定できる） |
| B. Webhook | アクション グループのオプションに含まれる | ❌（設定できる） |
| C. DB バックアップの直接実行 | アクション グループの直接オプションには含まれない | ✅ 正解（設定できない） |
| D. Logic App のトリガー | アクション グループのオプションに含まれる | ❌（設定できる） |

</details>

## 問題 4

SQL Server の重要なパフォーマンス メトリックとして、動的管理ビュー（DMV）からのみ取得でき、Windows PerfMon では取得できないメトリックの例はどれですか？

- A. CPU 使用率（Processor % Processor Time）
- B. ディスク読み取り/書き込みの秒数
- C. `sys.dm_os_volume_stats` が提供するトランザクション ログの読み書き待機時間
- D. バッファーキャッシュヒット率

<details>
<summary>解答・解説</summary>

**解答:** C

`sys.dm_os_volume_stats` が提供するデータ（トランザクション ログ ファイルの読み取り・書き込み待機時間など）は DMV からしか取得できず、PerfMon では公開されていません。一方、CPU 使用率やバッファーキャッシュヒット率は PerfMon のカウンターとして公開されています。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. CPU 使用率 | PerfMon でも取得可能 | ❌ |
| B. ディスク読み書き秒数 | PerfMon の PhysicalDisk カウンターで取得可能 | ❌ |
| C. dm_os_volume_stats の待機時間 | DMV からのみ取得可能 | ✅ 正解 |
| D. バッファーキャッシュヒット率 | PerfMon の SQLServer:Buffer Manager カウンターで取得可能 | ❌ |

</details>

## 問題 5

Azure Monitor のメトリック データについて正しい説明はどれですか？

- A. デフォルトで 1 年間保持される
- B. 93 日間保持され、それ以降は Azure Storage にアーカイブすることもできる
- C. Log Analytics ワークスペースに自動的に転送され、無期限に保存される
- D. 保存期間は変更できない

<details>
<summary>解答・解説</summary>

**解答:** B

Azure Monitor のアクティブなメトリック データは 93 日間保持されます。長期保存が必要な場合は Azure Storage へのアーカイブが可能です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. 1 年間保持 | 正しくない。93 日間 | ❌ |
| B. 93 日間、アーカイブ可能 | 正確な説明 | ✅ 正解 |
| C. Log Analytics に自動転送・無期限 | 自動転送は設定が必要。無期限でもない | ❌ |
| D. 保存期間変更不可 | アーカイブにより実質延長可能 | ❌ |

</details>
