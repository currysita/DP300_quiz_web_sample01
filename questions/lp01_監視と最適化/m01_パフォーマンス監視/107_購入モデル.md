# 監視107 — Azure SQL Database の購入モデル（vCore / DTU）

> 参考: [Azure SQL Database の購入モデル](https://learn.microsoft.com/ja-jp/azure/azure-sql/database/purchasing-models)

---

## 問題 1

Azure SQL Database の購入モデルは2種類あります。2つのモデルの組み合わせとして正しいものはどれですか？

- A. vCore モデルと eDTU モデル
- B. vCore モデルと DTU モデル
- C. 仮想コアモデルとサーバーレスモデル
- D. Standard モデルと Premium モデル

<details>
<summary>解答・解説</summary>

**解答:** B

Azure SQL Database の購入モデルは **vCore（仮想コア）モデル** と **DTU（Database Transaction Unit）モデル** の2種類です。eDTU はエラスティックプール向けの単位であり、購入モデルの名称ではありません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. vCore と eDTU | eDTU はエラスティックプールの単位。購入モデルの名称ではない | ❌ |
| B. vCore と DTU | 正しい2つの購入モデル | ✅ 正解 |
| C. 仮想コアとサーバーレス | サーバーレスは vCore モデル内の課金オプション | ❌ |
| D. Standard と Premium | DTU モデルのサービス層の名称 | ❌ |

</details>

## 問題 2

DTU（Database Transaction Unit）の説明として最も正確なものはどれですか？

- A. 仮想マシンの仮想 CPU コア数を表す単位
- B. CPU・メモリ・読み取り・書き込みを組み合わせたバンドル化された測定値
- C. ストレージの I/O スループットを表す単位
- D. 1 秒あたりのトランザクション処理数

<details>
<summary>解答・解説</summary>

**解答:** B

DTU は CPU・メモリ・読み取り・書き込みを組み合わせた測定値です。これらのリソースの比率は一般的な OLTP ベンチマークワークロードに基づいて設計されており、個別のリソースを選ぶのではなく、まとめて選択します。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. 仮想 CPU コア数 | それは vCore の説明 | ❌ |
| B. CPU・メモリ・読み書きのバンドル | DTU の正確な定義 | ✅ 正解 |
| C. I/O スループット単位 | DTU はストレージ専用の単位ではない | ❌ |
| D. TPS（1秒あたりのトランザクション数） | DTU はそのような定義ではない | ❌ |

</details>

## 問題 3

vCore モデルにあって DTU モデルにない機能として正しいものを2つ選んでください。

- A. エラスティックプールのサポート
- B. Azure Hybrid Benefit による割引
- C. サーバーレス（自動一時停止・スケーリング）
- D. バックアップの保持期間設定

<details>
<summary>解答・解説</summary>

**解答:** B、C

vCore モデルではソフトウェア アシュアランスを持つ SQL Server ライセンスを使った **Azure Hybrid Benefit** の割引が利用でき、アイドル時に自動一時停止する **サーバーレス** オプションも使えます。どちらも DTU モデルには存在しません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. エラスティックプール | DTU モデルでも利用可能 | ❌ |
| B. Azure Hybrid Benefit | vCore モデルのみ | ✅ 正解 |
| C. サーバーレス | vCore モデルのみ | ✅ 正解 |
| D. バックアップ保持期間設定 | 両モデルで設定可能 | ❌ |

</details>

## 問題 4

DTU モデルのサービス層は3種類あります。正しい組み合わせはどれですか？

- A. Basic / Standard / Premium
- B. Free / Standard / Premium
- C. General Purpose / Business Critical / Hyperscale
- D. Basic / General Purpose / Business Critical

<details>
<summary>解答・解説</summary>

**解答:** A

DTU モデルのサービス層は **Basic・Standard・Premium** の3種類です。**General Purpose・Business Critical・Hyperscale** は vCore モデルのサービス層です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Basic / Standard / Premium | DTU モデルの3つのサービス層 | ✅ 正解 |
| B. Free / Standard / Premium | Free は正式なサービス層ではない | ❌ |
| C. General Purpose / Business Critical / Hyperscale | vCore モデルのサービス層 | ❌ |
| D. Basic / General Purpose / Business Critical | モデルが混在している | ❌ |

</details>

## 問題 5

vCore モデルのサービス層「Business Critical」の特徴として正しいものをすべて選んでください。（2 つ選択）

- A. ストレージはリモートの Premium Storage を使用する
- B. ローカル SSD ストレージを使用し、読み書き 1〜2 ms の低レイテンシーを実現する
- C. 読み取り専用のセカンダリ レプリカが 1 つ含まれており、追加費用なく利用できる
- D. 最大ストレージは 128 TB

<details>
<summary>解答・解説</summary>

**解答:** B、C

Business Critical は **ローカル SSD** を使用するため 1〜2 ms の低レイテンシーを実現します。また、3 つのレプリカ（メイン 1 + セカンダリ 2、うち 1 つは読み取り専用）を保持しており、読み取り専用セカンダリは追加費用なく利用可能です。最大 128 TB は Hyperscale の特徴です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. リモート Premium Storage | General Purpose の特徴 | ❌ |
| B. ローカル SSD・1〜2 ms | Business Critical の正しい特徴 | ✅ 正解 |
| C. 読み取り専用セカンダリを含む | Business Critical の正しい特徴 | ✅ 正解 |
| D. 最大 128 TB | Hyperscale の特徴 | ❌ |

</details>

## 問題 6

vCore モデルのサービス層「Hyperscale」についての説明として正しいものはどれですか？

- A. Azure SQL Managed Instance でも利用できる
- B. In-Memory OLTP をサポートしている
- C. 最大ストレージは 128 TB で、コンピュートとストレージを独立してスケーリングできる
- D. General Purpose より低コストで、すべてのワークロードに推奨される

<details>
<summary>解答・解説</summary>

**解答:** C

Hyperscale は最大 128 TB のストレージを持ち、コンピュートとストレージを独立してスケーリングできるクラウドネイティブなアーキテクチャです。**Azure SQL Managed Instance では利用できません**。In-Memory OLTP は非対応です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Managed Instance でも利用可 | Hyperscale は Azure SQL Database のみ | ❌ |
| B. In-Memory OLTP サポート | Hyperscale は In-Memory OLTP 非対応 | ❌ |
| C. 最大 128 TB・独立スケーリング | Hyperscale の正しい特徴 | ✅ 正解 |
| D. すべてのワークロードに推奨 | 用途は大容量・高スケーリング要件向け | ❌ |

</details>

## 問題 7

Azure SQL Managed Instance がサポートする購入モデルはどれですか？

- A. DTU モデルのみ
- B. vCore モデルのみ
- C. DTU モデルと vCore モデルの両方
- D. どちらのモデルも使わず、独自の課金モデルを持つ

<details>
<summary>解答・解説</summary>

**解答:** B

Azure SQL Managed Instance は **vCore モデルのみ** をサポートしています。DTU モデルは Azure SQL Database 単体（エラスティックプール含む）でのみ使用できます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. DTU モデルのみ | Managed Instance は DTU 非対応 | ❌ |
| B. vCore モデルのみ | 正しい | ✅ 正解 |
| C. 両方 | DTU は Managed Instance では使えない | ❌ |
| D. 独自モデル | vCore モデルを使用している | ❌ |

</details>

## 問題 8

次のシナリオに最も適した vCore モデルのサービス層を選択してください。「ストレージが急増する可能性があり、将来的に 20 TB を超えることが想定される。コンピュートとストレージを独立してスケーリングしたい。」

- A. General Purpose
- B. Business Critical
- C. Hyperscale
- D. DTU の Premium

<details>
<summary>解答・解説</summary>

**解答:** C

General Purpose と Business Critical の最大ストレージは 4 TB です。20 TB 超が想定される場合は最大 128 TB まで拡張でき、コンピュートとストレージを独立してスケーリングできる **Hyperscale** が適切です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. General Purpose | 最大ストレージ 4 TB | ❌ |
| B. Business Critical | 最大ストレージ 4 TB | ❌ |
| C. Hyperscale | 最大 128 TB・独立スケーリング | ✅ 正解 |
| D. DTU の Premium | 最大 4 TB・vCore モデルではない | ❌ |

</details>

## 問題 9

vCore モデルの「サーバーレス（Serverless）」コンピュートの特徴として正しいものはどれですか？

- A. ストレージも自動的にゼロにスケールダウンする
- B. コンピュートが自動スケーリングされ、アイドル時は一時停止して秒単位で課金される
- C. Hyperscale サービス層でのみ使用できる
- D. DTU モデルでも同様の機能が利用できる

<details>
<summary>解答・解説</summary>

**解答:** B

サーバーレスはアクティビティに応じてコンピュートが自動スケーリングされ、アイドル期間は自動一時停止します。課金は使用した分を秒単位で行います（プロビジョニング型は時間単位で固定課金）。サーバーレスは vCore モデル専用で、DTU モデルには存在しません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ストレージもゼロにスケール | ストレージは一時停止中も保持され課金が続く | ❌ |
| B. 自動スケーリング・秒単位課金 | サーバーレスの正確な説明 | ✅ 正解 |
| C. Hyperscale のみ | General Purpose でも使用可能 | ❌ |
| D. DTU でも同様の機能あり | DTU モデルにサーバーレスはない | ❌ |

</details>
