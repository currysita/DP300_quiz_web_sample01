## 問題 1

拡張イベントのチャネル「操作（Operational）」の用途として最も適切な説明はどれですか？

- A. 開発者がデバッグ目的で使用する内部チャネル
- B. パフォーマンス イベントを大量に発行するトレース用チャネル
- C. 分析・診断または一般的な問題のイベント。特定の事象に基づいてアクションをトリガーするために使用
- D. エンド ユーザーと管理者を対象とした明確なアクション内の問題を示すチャネル

<details>
<summary>解答・解説</summary>

**解答:** C

「操作（Operational）」チャネルは分析・診断に使用されます。例として、可用性グループのデータベース状態変化（フェールオーバーの示唆）があります。イベントの発生に基づいてアクションやタスクをトリガーするために使えます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. デバッグ用内部チャネル | それは「デバッグ」チャネルの説明 | ❌ |
| B. パフォーマンス イベントの大量発行 | それは「分析（Analytic）」チャネルの説明 | ❌ |
| C. 診断・アクション トリガー | 操作チャネルの正しい説明 | ✅ 正解 |
| D. 管理者向け明確なアクション内の問題 | それは「管理者（Admin）」チャネルの説明 | ❌ |

</details>

## 問題 2

拡張イベント ターゲット「ring_buffer（リング バッファー）」の特性として正しいものはどれですか？

- A. ディスク上のファイルに永続保存する
- B. イベントの発生回数のみをカウントする同期ターゲット
- C. メモリ内に循環保存し、セッション終了後にデータが消える非同期ターゲット
- D. Windows OS イベントと SQL Server イベントを関連付ける同期ターゲット

<details>
<summary>解答・解説</summary>

**解答:** C

ring_buffer はメモリ内にデータを保持する循環バッファーです。データはディスクに永続化されず、バッファーがいっぱいになると古いデータから上書きされます。主にライブ観察に使われます。処理は非同期です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ディスクに永続保存 | event_file の説明 | ❌ |
| B. 発生回数のみカウントする同期 | event_counter の説明 | ❌ |
| C. メモリ内循環保存・非同期 | ring_buffer の正確な説明 | ✅ 正解 |
| D. OS イベントと関連付ける同期 | ETW（Event Tracing for Windows）の説明 | ❌ |

</details>

## 問題 3

拡張イベント セッションでフィルター `sqlserver.is_system = 0` を設定した場合の効果はどれですか？

- A. システム データベースのみを監視対象にする
- B. システム接続（内部操作）によるイベントを除外し、ユーザー接続のイベントのみを収集する
- C. is_system が 0 のデータベースのみを対象にする
- D. フィルターをかけたイベントを同期処理する

<details>
<summary>解答・解説</summary>

**解答:** B

`sqlserver.is_system = 0` は「システム接続ではない（＝ユーザー/アプリケーション接続）」を意味します。これにより内部システム操作のイベントが除外され、ユーザーのクエリだけが収集されます。データ収集のノイズを減らし、分析効率を高めます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. システム DB のみを対象 | is_system フィルターは接続種別でありDB種別ではない | ❌ |
| B. ユーザー接続のみを収集 | 正しい解釈 | ✅ 正解 |
| C. is_system=0 のDB対象 | そのような動作はしない | ❌ |
| D. 同期処理に変わる | フィルターは処理モードに影響しない | ❌ |

</details>

## 問題 4

同期処理で動作する拡張イベント ターゲットはどれですか？（2 つ選択）

- A. event_file
- B. event_counter
- C. ring_buffer
- D. ETW（Event Tracing for Windows）

<details>
<summary>解答・解説</summary>

**解答:** B、D

拡張イベント ターゲットのほとんどは非同期処理ですが、event_counter と ETW は同期処理で動作します。event_file・ring_buffer・histogram・event_pairing は非同期処理です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. event_file | 非同期 | ❌ |
| B. event_counter | 同期処理 | ✅ 正解 |
| C. ring_buffer | 非同期 | ❌ |
| D. ETW | 同期処理 | ✅ 正解 |

</details>

## 問題 5

拡張イベント セッションに「因果関係の追跡（causality tracking）」を有効にすると何が追加されますか？

- A. イベントごとのスタック トレース
- B. GUID とシーケンス番号。イベントの発生順序を追跡できる
- C. イベントのフィルタリング条件
- D. SQL Server のバージョン情報

<details>
<summary>解答・解説</summary>

**解答:** B

因果関係の追跡を有効にすると、各イベントの出力にグローバル一意識別子（GUID）とシーケンス番号が追加されます。これにより複数のイベントが発生した順序の流れを確認しやすくなります。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. スタック トレース | 因果関係の追跡の機能ではない | ❌ |
| B. GUID とシーケンス番号 | 正確な説明 | ✅ 正解 |
| C. フィルタリング条件 | フィルターは別途イベントごとに設定する機能 | ❌ |
| D. バージョン情報 | 因果関係の追跡の機能ではない | ❌ |

</details>

## 問題 6

Azure SQL Database（PaaS）で拡張イベントの event_file ターゲットを使用した場合、データはどこに書き込まれますか？

- A. SQL Server が稼働している VM のローカル ディスク
- B. Azure Files
- C. Azure Blob Storage
- D. Azure Data Lake Storage

<details>
<summary>解答・解説</summary>

**解答:** C

Azure SQL Database のような PaaS 環境では、event_file ターゲットのデータはローカル ファイル システムではなく Azure Blob Storage に書き込まれます。オンプレミスや IaaS の SQL Server では .xel ファイルとしてローカル ディスクに保存されます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. VM のローカル ディスク | PaaS では VM の直接制御がないため不可 | ❌ |
| B. Azure Files | event_file の書き込み先ではない | ❌ |
| C. Azure Blob Storage | PaaS での event_file の書き込み先 | ✅ 正解 |
| D. Azure Data Lake Storage | event_file の書き込み先ではない | ❌ |

</details>

## 問題 7

拡張イベント ターゲット「histogram（ヒストグラム）」の特徴として正しいものはどれですか？

- A. すべてのイベントをカウントする同期ターゲット
- B. ペアになるイベントの不一致を検出する
- C. 特定のイベント列またはアクションの値ごとにカウントできる非同期ターゲット
- D. メモリ内に循環保存する非同期ターゲット

<details>
<summary>解答・解説</summary>

**解答:** C

histogram は event_counter に似ていますが、特定のイベント列またはアクションの値ごとに件数を集計できる点が異なります。例えば「データベース名別のクエリ実行回数」のような分布を確認できます。処理は非同期です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. すべてカウントする同期 | event_counter の説明（event_counter は同期だが histogram は非同期） | ❌ |
| B. ペアの不一致検出 | event_pairing の説明 | ❌ |
| C. 列/アクション値ごとに集計する非同期 | histogram の正確な説明 | ✅ 正解 |
| D. 循環保存する非同期 | ring_buffer の説明 | ❌ |

</details>
