> 対応ユニット: [パフォーマンス監視ツールの説明](https://learn.microsoft.com/ja-jp/training/modules/describe-performance-monitoring/2-describe-performance-monitoring-tools)

## 問題 1

Azure 仮想マシン上の SQL Server を監視しています。CPU 使用率やネットワーク使用率など OS レベルのメトリックを Azure Portal で確認したい。どのサービスがこれらのメトリックを収集・表示しますか？

- A. Azure Log Analytics
- B. Azure Monitor
- C. SQL リソース プロバイダー
- D. Windows パフォーマンス モニター（PerfMon）

<details>
<summary>解答・解説</summary>

**解答:** B

Azure Monitor は、Azure リソースのメトリックの標準セットを収集・表示する包括的なプラットフォーム監視ソリューションです。仮想マシンにエージェントがインストールされると、CPU 使用率・ネットワーク使用率・ディスク読み書きなどの OS メトリックが Azure Monitor に送られます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Azure Log Analytics | ログデータの保存・クエリ用。メトリックの収集主体ではない | ❌ |
| B. Azure Monitor | VM エージェント経由で OS メトリックを収集・表示するプラットフォーム | ✅ 正解 |
| C. SQL リソース プロバイダー | SQL 固有の設定管理（パッチ適用・ストレージ構成）が目的 | ❌ |
| D. PerfMon | VM 内部でのローカル収集ツール。Portal での表示は不可 | ❌ |

</details>

## 問題 2

Azure 仮想マシン上の SQL Server で、バッファキャッシュヒット率や 1 秒あたりのバッチ要求数などの SQL Server エンジン固有のカウンターを収集する必要があります。最も適切なツールはどれですか？

- A. Azure Monitor のメトリック
- B. Azure アクティビティ ログ
- C. Windows パフォーマンス モニター（PerfMon）
- D. Azure SQL Database のクエリ パフォーマンス分析情報

<details>
<summary>解答・解説</summary>

**解答:** C

SQL Server をインストールすると OS にデータベース エンジン独自のパフォーマンス カウンターが登録されます。PerfMon はそれらを直接収集できます。Azure Monitor の標準メトリックは OS レベル（CPU・ディスク・ネットワーク）に限られ、SQL Server エンジン カウンターは含まれません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Azure Monitor のメトリック | OS レベルのインフラ メトリックのみ。SQL エンジン カウンターは対象外 | ❌ |
| B. Azure アクティビティ ログ | コントロール プレーン操作の記録。パフォーマンス情報は含まない | ❌ |
| C. PerfMon | SQL Server エンジン カウンターを含む Windows ネイティブ収集ツール | ✅ 正解 |
| D. クエリ パフォーマンス分析情報 | Azure SQL Database 専用機能。IaaS VM の SQL Server には使用不可 | ❌ |

</details>

## 問題 3

Azure Marketplace の SQL Server イメージから仮想マシンを作成すると、Azure Portal の VM ブレードで「SQL Server 構成」オプションが表示されました。このリソース プロバイダーが提供する機能として正しいものをすべて選択してください。（2 つ選択）

- A. データベース ファイルとトランザクション ログが使用しているストレージ容量の確認
- B. SQL Server エンジンのリアルタイム CPU 使用率のグラフ表示
- C. 自動パッチ適用の管理
- D. 拡張イベント セッションの作成

<details>
<summary>解答・解説</summary>

**解答:** A、C

SQL 仮想マシン リソース プロバイダー（SQL IaaS エージェント拡張機能）は、データベース/ログ ファイルのストレージ状況確認と、自動パッチ適用・ストレージ構成などの管理機能を提供します。リアルタイム CPU グラフは Azure Monitor、拡張イベントは SSMS 等を使います。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ストレージ容量の確認 | SQL IaaS エージェント拡張機能の提供機能 | ✅ 正解 |
| B. リアルタイム CPU グラフ | Azure Monitor / PerfMon の役割 | ❌ |
| C. 自動パッチ適用の管理 | SQL IaaS エージェント拡張機能の提供機能 | ✅ 正解 |
| D. 拡張イベント セッションの作成 | SSMS や T-SQL で行う操作 | ❌ |

</details>

## 問題 4

Azure Monitor の分析情報（Monitoring Insights）を有効にすると、標準エージェントでは収集されない追加メトリックを取得できます。収集されるようになるメトリックの例として正しいものはどれですか？

- A. SQL Server の 1 秒あたりのバッチ要求数
- B. ストレージの待機時間と使用可能なメモリ
- C. データベースのデッドロック発生回数
- D. クエリの平均実行時間

<details>
<summary>解答・解説</summary>

**解答:** B

Azure Monitoring Insights を有効にすると、ストレージの待機時間・使用可能なメモリ・ディスク容量など OS/インフラレベルの追加データポイントが収集されます。SQL Server 固有の情報（バッチ要求数・デッドロック・クエリ実行時間）は別ツールで取得します。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. バッチ要求数 | SQL Server エンジン カウンター。PerfMon で収集 | ❌ |
| B. ストレージ待機時間・使用可能メモリ | Monitoring Insights が追加収集するインフラ メトリック | ✅ 正解 |
| C. デッドロック発生回数 | 拡張イベント等で収集 | ❌ |
| D. クエリ平均実行時間 | Query Performance Insight / クエリ ストアで収集 | ❌ |

</details>

## 問題 5

Azure Monitor の Monitoring Insights が収集したデータはどこに格納されますか？

- A. Azure SQL Database
- B. Azure Blob Storage
- C. Azure Log Analytics ワークスペース
- D. Azure Data Explorer

<details>
<summary>解答・解説</summary>

**解答:** C

Azure Monitor の Monitoring Insights が収集したデータは Azure Log Analytics ワークスペースに格納されます。Log Analytics は各種ログを保存・クエリするための Azure の主要ツールであり、KQL（Kusto Query Language）を使って分析できます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Azure SQL Database | リレーショナル DB サービス。監視ログの格納先ではない | ❌ |
| B. Azure Blob Storage | 長期アーカイブ用途。Insights の既定格納先ではない | ❌ |
| C. Azure Log Analytics ワークスペース | Monitoring Insights データの既定格納先 | ✅ 正解 |
| D. Azure Data Explorer | Database Watcher 等が使用する時系列分析ストア | ❌ |

</details>

## 問題 6

Linux OS の Azure 仮想マシン上で SQL Server を実行しています。Windows の PerfMon に相当するパフォーマンスデータを収集するために使用するツールの組み合わせとして正しいものはどれですか？

- A. Azure Monitor + Log Analytics エージェント
- B. InfluxDB + Collectd + Grafana
- C. SSMS + 拡張イベント
- D. Azure Data Studio + クエリ ストア

<details>
<summary>解答・解説</summary>

**解答:** B

Linux 環境では InfluxDB（時系列 DB）、Collectd（メトリック収集デーモン）、Grafana（可視化 UI）を組み合わせることで、Windows の PerfMon に相当するパフォーマンス データ収集・可視化環境を構築できます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. Azure Monitor + Log Analytics | OS に依存しない Azure サービスだが、Linux PerfMon の直接代替ではない | ❌ |
| B. InfluxDB + Collectd + Grafana | Linux 上での PerfMon 相当の構成として公式ドキュメントで案内 | ✅ 正解 |
| C. SSMS + 拡張イベント | SQL Server 固有のトレース。OS メトリック収集ではない | ❌ |
| D. Azure Data Studio + クエリ ストア | クエリ パフォーマンス分析ツール。OS メトリック収集ではない | ❌ |

</details>
