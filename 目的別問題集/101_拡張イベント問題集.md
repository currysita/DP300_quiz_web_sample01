# DP-300 目的別問題集 101 — 拡張イベント（Extended Events）ターゲット

---

## 問題 1

SQL Server でクエリのタイムアウトを調査するために拡張イベントセッションを作成しました。収集したデータは不揮発性ストレージに永続化し、セッション終了後も参照できるようにする必要があります。どのターゲットを使用すべきですか？（一つ選択）

- A. ring_buffer
- B. event_file
- C. event_counter
- D. histogram

<details>
<summary>解答・解説</summary>

**解答:** B

event_file はイベントデータをディスク上のファイル（.xel ファイル）に非同期で書き込みます。セッションを停止または再起動した後でもデータが保持されるため、後から参照・分析が必要な場面に適しています。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ring_buffer | メモリ上に循環保存。セッション終了時にデータが消える | ❌ |
| B. event_file | .xel ファイルに永続保存。セッション終了後も参照可能 | ✅ 正解 |
| C. event_counter | イベントの発生回数を数えるだけでデータ内容は保持しない | ❌ |
| D. histogram | 列の値ごとに件数を集計するが、内容の永続化が目的ではない | ❌ |

</details>

## 問題 2

Azure SQL Database で拡張イベントセッションを使用してリアルタイムでクエリを観察したい。データの永続化は不要で、できるだけ低オーバーヘッドで現在の状況を確認したい。最も適切なターゲットはどれですか？（一つ選択）

- A. event_file
- B. etw_classic_sync_target
- C. ring_buffer
- D. pair_matching

<details>
<summary>解答・解説</summary>

**解答:** C

ring_buffer はイベントデータをメモリ上に循環保存します。セッション終了時にデータは消えますが、オーバーヘッドが低くリアルタイム観察に適しています。また Azure SQL Database でも使用可能です。

etw_classic_sync_target と pair_matching は SQL Server 専用であり、Azure SQL Database では使用できません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. event_file | 永続化が目的。リアルタイム観察には不要なオーバーヘッドが生じる | ❌ |
| B. etw_classic_sync_target | SQL Server 専用。Azure SQL Database では使用不可 | ❌ |
| C. ring_buffer | メモリ上に一時保存。低オーバーヘッドでリアルタイム観察に最適 | ✅ 正解 |
| D. pair_matching | SQL Server 専用。Azure SQL Database では使用不可 | ❌ |

</details>

## 問題 3

SQL Server で特定のイベントが 1 時間あたり何回発生しているかを集計したい。イベントの内容ではなく、発生回数だけが必要です。最も適切なターゲットはどれですか？（一つ選択）

- A. histogram
- B. event_counter
- C. ring_buffer
- D. event_file

<details>
<summary>解答・解説</summary>

**解答:** B

event_counter はイベントの発生回数のみをカウントします。イベントデータの内容を保持しないため、「何回発生したか」だけを知りたい場合に最も軽量で適切なターゲットです。

histogram は列の値ごとの件数を集計しますが、単純な発生回数カウントには event_counter が最適です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. histogram | 特定列の値ごとに件数を集計。単純な発生回数カウントとは用途が異なる | ❌ |
| B. event_counter | イベント発生回数のみをカウント。最も軽量で目的に合致 | ✅ 正解 |
| C. ring_buffer | イベント内容をメモリに保存。発生回数だけの集計には過剰 | ❌ |
| D. event_file | イベント内容をファイルに保存。発生回数だけの集計には過剰 | ❌ |

</details>

## 問題 4

SQL Server でデッドロックを調査するために拡張イベントを設定しています。ロックの取得（lock_acquired）は記録されているが、対応するロック解放（lock_released）が記録されていない状況を検出したい。どのターゲットを使用すべきですか？（一つ選択）

- A. ring_buffer
- B. histogram
- C. pair_matching
- D. event_counter

<details>
<summary>解答・解説</summary>

**解答:** C

pair_matching は対になるイベントのうち、片方だけが発生した場合を検出するターゲットです。「ロック取得はあったがロック解放がない」という状況の特定に最適です。なお pair_matching は SQL Server 専用であり、Azure SQL Database / Managed Instance では使用できません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ring_buffer | すべてのイベントをメモリに保存するが、対応する片方を検出する機能はない | ❌ |
| B. histogram | 列の値ごとに件数を集計。ペア検出の機能はない | ❌ |
| C. pair_matching | 対になるイベントの片方だけを検出する専用ターゲット | ✅ 正解 |
| D. event_counter | 発生回数を数えるだけ。ペア検出の機能はない | ❌ |

</details>

## 問題 5

SQL Server のパフォーマンス問題を調査するために拡張イベントセッションを設定しています。クエリを実行したユーザーの login_name 列の値ごとに、イベントの発生件数を集計したい。どのターゲットを使用すべきですか？（一つ選択）

- A. event_counter
- B. ring_buffer
- C. histogram
- D. pair_matching

<details>
<summary>解答・解説</summary>

**解答:** C

histogram は指定した列（例: login_name）の値ごとにイベントの発生件数を集計するターゲットです。「どのユーザーが何回イベントを発生させたか」を把握するのに最適です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. event_counter | イベント全体の発生回数のみをカウント。列の値ごとの集計はできない | ❌ |
| B. ring_buffer | イベント内容をメモリに保存するが、値ごとの集計機能はない | ❌ |
| C. histogram | 特定の列の値ごとに件数を集計。login_name ごとの集計に最適 | ✅ 正解 |
| D. pair_matching | 対になるイベントの片方を検出する。値ごとの集計とは用途が異なる | ❌ |

</details>

## 問題 6

Azure SQL Managed Instance 環境で拡張イベントセッションを構成しています。次のターゲットのうち、Azure SQL Managed Instance では使用できないものはどれですか？（該当するものをすべて選択）

- A. event_file
- B. pair_matching
- C. ring_buffer
- D. etw_classic_sync_target
- E. histogram

<details>
<summary>解答・解説</summary>

**解答:** B、D

pair_matching と etw_classic_sync_target は SQL Server 専用のターゲットです。Azure SQL Database および Azure SQL Managed Instance では使用できません。

event_file、ring_buffer、histogram、event_counter は SQL Server・Azure SQL Database・Managed Instance のすべてで使用できます。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. event_file | SQL Server・Azure SQL DB・Managed Instance すべてで使用可能 | ❌ |
| B. pair_matching | SQL Server 専用。Managed Instance では使用不可 | ✅ 正解 |
| C. ring_buffer | SQL Server・Azure SQL DB・Managed Instance すべてで使用可能 | ❌ |
| D. etw_classic_sync_target | SQL Server 専用。Managed Instance では使用不可 | ✅ 正解 |
| E. histogram | SQL Server・Azure SQL DB・Managed Instance すべてで使用可能 | ❌ |

</details>

## 問題 7

SQL Server の拡張イベントターゲットのうち、イベントの処理が同期で行われるものはどれですか？（該当するものをすべて選択）

- A. event_file
- B. event_counter
- C. ring_buffer
- D. etw_classic_sync_target
- E. histogram

<details>
<summary>解答・解説</summary>

**解答:** B、D

拡張イベントのターゲットには同期処理と非同期処理の 2 種類があります。同期ターゲットはイベント発生時に即時処理するため、パフォーマンスへの影響が大きくなる場合があります。

- **同期**: event_counter、etw_classic_sync_target
- **非同期**: event_file、ring_buffer、histogram、pair_matching

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. event_file | 非同期。ディスクへの書き込みは非同期で行われる | ❌ |
| B. event_counter | 同期。イベント発生時に即時カウントを更新する | ✅ 正解 |
| C. ring_buffer | 非同期。メモリへの書き込みは非同期で行われる | ❌ |
| D. etw_classic_sync_target | 同期。Windows ETW と連携するため同期処理が必要 | ✅ 正解 |
| E. histogram | 非同期。集計処理は非同期で行われる | ❌ |

</details>

## 問題 8

SQL Server のパフォーマンス問題を調査しています。SQL Server のイベントデータを Windows の ETW（Event Tracing for Windows）と連携させて、OS レベルのトレースと組み合わせて分析したい。どのターゲットを使用すべきですか？（一つ選択）

- A. ring_buffer
- B. event_file
- C. pair_matching
- D. etw_classic_sync_target

<details>
<summary>解答・解説</summary>

**解答:** D

etw_classic_sync_target は SQL Server の拡張イベントを Windows の ETW（Event Tracing for Windows）と連携させるターゲットです。OS レベルのイベントと SQL Server のイベントを組み合わせた分析が可能になります。このターゲットは SQL Server 専用であり、Azure SQL Database / Managed Instance では使用できません。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ring_buffer | メモリに一時保存。Windows ETW との連携機能はない | ❌ |
| B. event_file | ファイルに永続保存。Windows ETW との連携機能はない | ❌ |
| C. pair_matching | 対になるイベントの片方を検出。ETW 連携の機能はない | ❌ |
| D. etw_classic_sync_target | SQL Server イベントを Windows ETW と連携させる専用ターゲット | ✅ 正解 |

</details>

## 問題 9

Azure SQL Database で拡張イベントセッションを作成し、.NET アプリケーション（C#）からリアルタイムでイベントデータを受信したい。どのターゲットを使用すべきですか？（一つ選択）

- A. ring_buffer
- B. event_stream
- C. event_file
- D. histogram

<details>
<summary>解答・解説</summary>

**解答:** B

event_stream は .NET プログラム（C# 等）からリアルタイムでイベントデータを受信するためのターゲットです。Azure SQL Database でも使用可能ですが、T-SQL（CREATE EVENT SESSION の ADD TARGET 句）からは追加できず、.NET SDK を通じてのみ利用できます。

ring_buffer もリアルタイムに近い観察はできますが、.NET アプリケーションからのリアルタイム受信という要件には event_stream が適切です。

| 選択肢 | 説明 | 正否 |
|---|---|---|
| A. ring_buffer | メモリに一時保存。.NET からのリアルタイム受信には対応していない | ❌ |
| B. event_stream | .NET プログラムからリアルタイムでイベントを受信できる専用ターゲット | ✅ 正解 |
| C. event_file | ファイルに永続保存。リアルタイム受信には適さない | ❌ |
| D. histogram | 列の値ごとに件数を集計。リアルタイム受信の機能はない | ❌ |

</details>
